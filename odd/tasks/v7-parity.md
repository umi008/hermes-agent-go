## Specs

- S1 Fallback providers: `fallback_providers` (and legacy `fallback_model`) from `config.yaml`; when the primary provider is exhausted, the agent moves to the next entry of the chain, as upstream.
- S2 `delegate_task`: subagents, as upstream `tools/delegate_tool*.py`.
- S3 Auxiliary side-LLM routing: compression summaries and other side calls use the auxiliary model when configured.
- S4 Other shell hook events beyond `pre_tool_call` and `post_tool_call`.
- S5 MCP resources and prompts utility tools; reconnect with backoff.
- S6 API server: `/v1/responses`, `/v1/runs`, `/api/sessions`.
- S7 Smart (LLM) approval gate, as upstream `tools/approval_smart.py` with `approvals.mode: smart`: the auxiliary LLM reviews every flagged command before any human, and its verdict is one of APPROVE, DENY or ESCALATE.
  - `approve` runs the command for this one operation and persists nothing; the session denial tally resets. The port logs it structurally (slog `smart approval: auto-approved` with `command` and `description`) instead of upstream's formatted line.
  - `deny` with no human present blocks with `BLOCKED by smart approval: {description}. The command was assessed as genuinely dangerous. Do NOT retry.`; with a human present the prompt is reduced to `      [o]nce  |  [d]eny` / `      Choice [o/D]: ` and nothing is persisted.
  - `escalate`, any other answer, an empty answer, or a failed call follows the normal human path unchanged.
  - The command is untrusted: shell comments are stripped before assessment and the wrapped in `<command>` delimiters; operator `approvals.smart_policy` is appended to the guardian system prompt only.
  - `approvals.denial_breaker_threshold` (default 3, 0 or negative disables) appends ` CIRCUIT BREAKER: {n} consecutive commands were blocked by the security reviewer. STOP attempting variations of this operation. Report the blocked operation to the user and either ask them to run it manually or use /approve.` to a deny once the session tally reaches it, and logs `Smart-approval circuit breaker tripped for session {s}: {n} consecutive denials (threshold {t})`.
  - `auxiliary.approval` (route, model, `timeout`, default 30 s) decides the assessing model; the call is temperature 0 with `max_tokens` 16.
- S8 TUI canonical wire: `session_authority`, resume, session list, slash commands.
- S9 Agent loop robustness: Retry-After honoring, `max_tokens` continuation.
- S10 File tools: further fuzzy `patch` strategies, `.gitignore` filtering in `search_files`.

Assumptions:
- Order follows user-visible value: S1 first (a single provider outage stops the agent today), then S2.
- Rows marked `out` in PARITY stay out unless the owner reopens them.
